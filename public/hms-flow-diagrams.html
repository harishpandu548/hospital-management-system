3. Authentication Flow

Login, token generation, and request validation for all portals

Login Flow — POST /api/auth/login

flowchart TD START(["User enters phone + password"]) --> REQ["POST /api/auth/login"] REQ --> FIND["Find user by phone in DB"] FIND --> FOUND{User found?} FOUND -- "❌ No" --> E1["401 Invalid credentials"] FOUND -- "✅ Yes" --> BCRYPT["bcryptjs.compare(password, hash)"] BCRYPT --> MATCH{Password matches?} MATCH -- "❌ No" --> E1 MATCH -- "✅ Yes" --> STATUS{Check user status} STATUS -- "SUSPENDED" --> E2["403 Account suspended"] STATUS -- "DELETED" --> E3["401 Account not found"] STATUS -- "ACTIVE ✅" --> ROLES["Load roles from UserRole table"] ROLES --> MULTI{Multiple roles?} MULTI -- "Yes" --> PICK["Return role list\nUser selects role"] PICK --> SIGN MULTI -- "No" --> SIGN["jwt.sign(userId + activeRole)\nexpires in 1 hour"] SIGN --> RESP["Return: { token, activeRole, name }"] RESP --> STORE["Client stores in\nlocalStorage.hms_token"] STORE --> USE["Every API request:\nAuthorization: Bearer token"] USE --> VERIFY["getAuthContext(req)\nverify signature + expiry\nvalidate role in DB"] VERIFY --> VALID{Valid?} VALID -- "❌ Expired/Invalid" --> E4["401 Unauthorized"] VALID -- "✅ OK" --> ACCESS["{ userId, activeRole } extracted\nRoute handler proceeds"] style START fill:#0d2818,stroke:#16a34a,color:#4ade80 style E1 fill:#3a0d0d,stroke:#dc2626,color:#f87171 style E2 fill:#3a0d0d,stroke:#dc2626,color:#f87171 style E3 fill:#3a0d0d,stroke:#dc2626,color:#f87171 style E4 fill:#3a0d0d,stroke:#dc2626,color:#f87171 style SIGN fill:#1a0d2e,stroke:#7c3aed,color:#a78bfa style ACCESS fill:#0d1f3c,stroke:#2563eb,color:#60a5fa

The Core Idea — One Shared Database, 4 Portals

All 4 portals talk to the same PostgreSQL database through the same API routes. There is no separate database per portal. When one portal writes data, all other portals instantly see it.
